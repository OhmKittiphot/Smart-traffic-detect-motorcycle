# CCTV Admin Dashboard (Django)

เว็บสำหรับผู้ดูแลระบบ ใช้ดูภาพจากกล้องหรือไฟล์วิดีโอพร้อมผลตรวจจับ และดูรายการรถที่ขับผ่าน
แถวสีเขียวคือรถปกติ แถวสีแดงคือรถที่ทำผิดกฎ ได้แก่ ไม่สวมหมวกกันน็อก, ซ้อนเกิน `max_riders` คน และขับเร็วเกิน `speed_limit_kmh`

## เริ่มใช้งาน

ใช้ Python จาก venv ของโปรเจกต์ (`venv\`) เสมอ รันจากโฟลเดอร์รากของโปรเจกต์:

```bash
venv\Scripts\python -m pip install -r requirements.txt
venv\Scripts\python web\manage.py createsuperuser
venv\Scripts\python web\run.py
```

เปิด http://127.0.0.1:8000 แล้วเข้าสู่ระบบด้วยบัญชีที่สร้างไว้ ระบบตรวจจับทำงานเฉพาะตอนที่มี staff เปิดหน้า Live view อยู่ ตอนเปิดหน้าจะใช้เวลาโหลดโมเดลประมาณ 10–30 วินาที และเมื่อไม่มีใครเปิดหน้า Live view (ออกจากหน้า หรือสลับไปแท็บอื่น) นาน 60 วินาที ระบบจะหยุดตรวจจับและคืนหน่วยความจำ GPU (`IDLE_STOP_S` ใน `dashboard/engine.py`) ส่วนการออกจากระบบ (logout) ของคนสุดท้ายที่เปิด Live view อยู่ จะหยุดตรวจจับทันที (ถ้ายังมีคนอื่นดูอยู่ ระบบจะทำงานต่อ)

## Role และ permission

ใช้ระบบ permission ของ Django: role คือ Group ส่วนหน้าเว็บของเราใช้ custom permission 4 ตัว (`dashboard.models.Access`) middleware ใน `dashboard/middleware.py` เช็กด้วย `user.has_perm(...)` ตาม path ถ้าเปิดหน้าที่ไม่มีสิทธิ์ ระบบจะพาไปหน้าแรกที่มีสิทธิ์ ถ้าไม่มีสิทธิ์เลยจะเข้าระบบไม่ได้

| permission | ใช้ทำอะไร | หน้า |
|---|---|---|
| `use_dashboard` | ดูภาพสด เปลี่ยนแหล่งวิดีโอ ตั้งค่าวัดความเร็ว ยืนยัน/ปฏิเสธเหตุการณ์ | `/` และ API ที่เหลือ |
| `view_records` | ค้นหาทะเบียน ดูภาพหลักฐาน และสถิติการฝ่าฝืน (ดูอย่างเดียว) | `/violations/`, `/search/` |
| `view_system_status` | ตรวจสอบสถานะกล้องและระบบ | `/system/` |
| `manage_calibration` | แก้ระยะจริง (กว้าง × ยาว) หรือลบค่าวัดความเร็วที่บันทึกไว้ ของกล้อง/ไฟล์ใดก็ได้ และวาง 4 จุดใหม่ได้เฉพาะแหล่งที่กำลังประมวลผลอยู่และมีสัญญาณ | `/system/` |
| `delete_records` | ลบรายการรถพร้อมภาพหลักฐาน ทั้งที่เลือกในหน้า Violations และปุ่ม Delete all ในหน้า Live view (ปุ่มนี้ซ่อนถ้าไม่มีสิทธิ์) | `/violations/`, `/` |
| `manage_settings` | ตั้งกติกาการฝ่าฝืนและระยะเวลาเก็บข้อมูล | Settings |

| Role (Group) | permission |
|---|---|
| **Staff** | `use_dashboard`, `view_records` (จัดการผู้ใช้ไม่ได้) |
| **Admin** | `view_records` (หน้า Violations: สถิติการฝ่าฝืน + ค้นหา), จัดการ User/Group ใน `/admin/`, `view_system_status`, `manage_calibration`, `delete_records` และ `manage_settings` |

- `migrate` สร้าง Group ทั้งสองพร้อม permission และบัญชี staff เริ่มต้น (username `staff`, password `staff`) **ควรเปลี่ยนรหัสผ่านก่อนใช้งานจริง** บัญชี superuser ที่มีอยู่ก่อนจะถูกเปลี่ยนเป็น Admin ธรรมดา เพราะ superuser มีทุก permission
- เพิ่มผู้ใช้ใน `/admin/` แล้วเลือก Group สำหรับ Admin ต้องติ๊ก **Staff status** ด้วย (Django ใช้ค่านี้ตัดสินว่าใครเข้า `/admin/` ได้) ส่วน Staff ไม่ต้องติ๊ก
- Admin ตั้งใครเป็น superuser ไม่ได้ (`RoleUserAdmin` ใน `dashboard/admin.py`) ส่วน superuser ที่สร้างด้วย `createsuperuser` มีทุก permission จึงเข้าได้ทุกหน้า ใช้สำหรับนักพัฒนาเท่านั้น
- แก้ permission ของแต่ละ Group หรือสร้าง role ใหม่ได้ใน `/admin/` → Groups โดยไม่ต้องแก้โค้ด
- **สถานะระบบ** (`/system/`): ตรวจสุขภาพระบบตรวจจับทุก 5 วินาทีโดยไม่สั่งให้มันเริ่มทำงาน (Standby = ไม่มีใครเปิด Live view, Starting, Healthy, Problem เช่น thread หรือ process OCR หยุด, Error), แหล่งวิดีโอที่ใช้อยู่, จำนวนรายการวันนี้ / ทั้งหมด, การฝ่าฝืนที่ยังไม่ได้ review, สถานะกล้องสดทุกตัว (ทดสอบเชื่อมต่อทุก 30 วินาที) และไฟล์วิดีโอที่มี พร้อมบอกว่าแหล่งไหนกำลังใช้อยู่และตั้งค่าวัดความเร็วแล้วหรือยัง (`dashboard/system_health.py`)

- **กล้องสด**: ใช้ `RTSP_URL` จาก `.env` ถ้าไม่ได้ตั้งค่าไว้ หรือกล้องไม่ส่งภาพเกิน 5 วินาที หน้าจอจะแสดง **NO SIGNAL**
- **กล้อง CCTV มูลนิธิ iTIC (ส่วนเสริม)**: เมื่อเลือกกล้องสด จะมี dropdown ให้เลือกระหว่าง IP camera กับกล้อง iTIC ฉะเชิงเทรา (ccs06) ส่วนเสริมนี้อยู่ใน `web/dashboard/itic_cameras.py` ถ้าลบไฟล์นี้ dropdown จะหายไป และระบบจะกลับไปใช้ IP camera
- **ไฟล์วิดีโอ**: เลือกได้เฉพาะไฟล์ที่อยู่ในโฟลเดอร์ `input/` เมื่อเล่นจบ วิดีโอจะกลับไปเฟรมแรกแล้วหยุดรอ (ไม่วนซ้ำ)
- **หน้า Violations** (`/violations/`): สถิติการฝ่าฝืนอยู่ส่วนบน และมีช่องค้นหาทะเบียนอยู่ข้างล่าง (ติ๊ก Violations only ไว้ให้ตั้งแต่เปิดหน้า) สถิติประกอบด้วย จำนวนการฝ่าฝืนวันนี้ / 7 วัน / 30 วัน, สัดส่วนเทียบกับรถทั้งหมด, แยกตามประเภท และรายวัน (`/api/stats/`)
- **หน้าค้นหาทะเบียน** (`/search/`, ปุ่ม Search plate ต่อจาก filter ในตาราง และที่แถบบน): มีแค่ช่องค้นหา หาทะเบียนที่ใกล้เคียงแม้ OCR อ่านผิดหรืออ่านได้ไม่ครบ ระบบแยกเทียบหมวดอักษร (`6มก`) กับเลขทะเบียน (`65`) ทีละส่วน ส่วนที่ OCR อ่านไม่ได้จะไม่นำมาคิด เช่นค้น `6มก65` จะเจอป้ายที่ระบบอ่านได้แค่ `65` ตัวอักษรที่หน้าตาคล้ายกัน (บ/ป, ด/ต, 3/8 …) นับว่าใกล้เคียง ค้นหลายป้ายพร้อมกันได้โดยคั่นด้วยจุลภาค เช่น `1กข987, 2847` (สูงสุด 10 ป้าย) ผลเรียงจากป้ายที่ใกล้ที่สุดก่อน (`dashboard/plate_search.py`)
- **ยืนยันเหตุการณ์**: ในหน้าค้นหา กดแถวใดก็ได้เพื่อดูรายละเอียดและภาพหลักฐาน แล้วกด **Confirm event** (ยืนยัน) หรือ **Reject** (ไม่ถูกต้อง) พร้อมใส่หมายเหตุได้ ระบบบันทึกว่าใครยืนยันเมื่อไร (ดูได้ใน `/admin/` และบันทึกการใช้งาน) และกด Undo review เพื่อยกเลิกได้
- **ภาพหลักฐาน**: กดรูปเล็กในตาราง เพื่อดูภาพรถและคนขี่ตอนที่รถอยู่ใกล้กล้องที่สุด ถ้าตรวจเจอป้ายทะเบียน จะเก็บภาพป้ายที่คมที่สุดของรถคันนั้นไว้ด้วย (แสดงข้างเลขทะเบียน และในหน้ารายละเอียด) แม้ OCR จะอ่านไม่ออกก็ตาม
- **ตั้งค่า** (ปุ่ม Settings มุมขวาบนของทุกหน้า เปิดเป็นหน้าต่างเล็ก ไม่ต้องเปลี่ยนหน้า): Admin ตั้งกติกาการฝ่าฝืน (ความเร็วสูงสุด, จำนวนคนซ้อน) ซึ่งมีผลทันทีแม้ระบบตรวจจับกำลังทำงาน และตั้งระยะเวลาเก็บข้อมูลพร้อมปุ่ม Clean up now ส่วน Staff ตั้งค่าหน้า Live view ของบัญชีตัวเอง (ตัวกรองตารางเริ่มต้น, ระยะข้ามวิดีโอ, แสดงกราฟ FPS) ซึ่งบันทึกทันทีที่เปลี่ยนและมีผลกับหน้า Live view ที่เปิดอยู่เลย บัญชีที่ดูรายการได้ (Staff และ Admin) เปิด **แจ้งเตือนการฝ่าฝืนใหม่** ได้ (ค่าเริ่มต้นปิด) จะมีกล่องแจ้งเตือนเด้งที่มุมขวาล่างไม่ว่าอยู่หน้าไหน ทุกบัญชีเปลี่ยนรหัสผ่านตัวเองได้ การเปลี่ยนกติกา การล้างข้อมูล และการเปลี่ยนรหัสผ่านถูกบันทึกในบันทึกการใช้งาน
- **จัดการผู้ใช้และดูประวัติ** (Admin): ไปที่ `/admin/` เพื่อเพิ่มหรือลบผู้ใช้ กำหนด role และดูบันทึกว่าใครเปลี่ยนแหล่งวิดีโอ
- **API ภายใน**: หน้า dashboard คุยกับ server ผ่าน `/api/...` ซึ่งเขียนด้วย Django REST Framework แบบ `APIView` + `Serializer` (`dashboard/views/` และ `dashboard/serializers.py`) ใช้ได้เฉพาะจากหน้า dashboard ที่ล็อกอินแล้ว

## พื้นที่จัดเก็บ

ภาพหลักฐานและรายการรถถูกคุมไม่ให้เกินพื้นที่ที่กำหนด (`dashboard/storage.py`) โดย `run.py` ล้างข้อมูลตอนเริ่ม และทุก 6 ชั่วโมง หรือสั่งเองได้ด้วย `venv\Scripts\python web\manage.py cleanup` (หรือปุ่ม Clean up now ในหน้า Settings) `SNAPSHOT_MAX_SIDE` ตั้งใน `.env` ส่วนอีก 3 ค่าใน `.env` เป็นแค่ค่าเริ่มต้นตอนติดตั้ง หลังจากนั้น Admin ปรับได้ในหน้า Settings

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `SNAPSHOT_MAX_SIDE` | 720 | ย่อภาพรถให้ด้านยาวสุดไม่เกินกี่พิกเซลตอนบันทึก (ภาพป้ายเล็กอยู่แล้ว ไม่ย่อ) |
| `PHOTO_RETENTION_DAYS` | 7 | รถปกติและเหตุการณ์ที่ Reject แล้ว ลบภาพหลังกี่วัน (รายการยังอยู่ สถิติไม่เปลี่ยน) |
| `RECORD_RETENTION_DAYS` | 90 | ลบรายการพร้อมภาพหลังกี่วัน |
| `MEDIA_MAX_MB` | 2048 | ภาพรวมกันได้สูงสุดกี่ MB ถ้าเกิน จะลบภาพเก่าสุดของรถปกติก่อน แล้วค่อยเป็นการฝ่าฝืนที่ยังไม่ตรวจ จนเหลือ 90% |

เหตุการณ์ที่ **Confirm แล้ว** ไม่ถูกลบอัตโนมัติเลย เพราะเป็นหลักฐาน ต้องลบเองจากหน้า Violations ไฟล์ภาพที่ไม่มีรายการอ้างถึง (เช่นลบรายการผ่าน `/admin/`) ก็ถูกลบด้วย หน้า System status แสดงพื้นที่ที่ภาพ ฐานข้อมูล และดิสก์ใช้อยู่

## ความปลอดภัย

- ทุกหน้าต้องเข้าสู่ระบบ และแต่ละหน้าเปิดได้เฉพาะบัญชีที่มี permission ของหน้านั้น
- ถ้าใส่รหัสผ่านผิด 5 ครั้ง บัญชีนั้นจาก IP นั้นจะถูกล็อก 15 นาที (django-axes)
- session มีอายุสูงสุด 8 ชั่วโมงและหมดอายุเมื่อปิดเบราว์เซอร์ คุกกี้ตั้งเป็น HttpOnly และ SameSite=Strict
- มี CSRF ป้องกันทุกคำสั่ง POST และตั้ง CSP แบบเข้มงวด (ไม่มี inline script และไม่โหลดอะไรจากโดเมนอื่น)
- ภาพหลักฐานส่งผ่าน view ที่ต้องล็อกอินเท่านั้น ไม่มี URL สาธารณะ
- ไม่ส่ง URL ของกล้อง (ซึ่งมีรหัสผ่าน) ไปที่เบราว์เซอร์ และไม่พิมพ์ลง log
- server ฟังเฉพาะ `127.0.0.1` เป็นค่าเริ่มต้น

ตัวแปรเพิ่มเติมใน `.env` (ไม่ต้องตั้งก็ได้):

| ตัวแปร | ความหมาย |
|---|---|
| `DASHBOARD_HOST` / `DASHBOARD_PORT` | ค่าเริ่มต้นคือ `127.0.0.1` / `8000` ถ้าตั้งเป็น `0.0.0.0` คนอื่นในเครือข่ายจะเข้าได้ |
| `DJANGO_ALLOWED_HOSTS` | ชื่อโฮสต์หรือ IP ที่อนุญาต คั่นด้วย `,` ต้องตั้งเมื่อเปิดให้เครื่องอื่นเข้า |
| `DJANGO_HTTPS=1` | เปิด secure cookies, HSTS และ redirect ไป HTTPS (ใช้เมื่อมี HTTPS แล้ว) |
| `DJANGO_BEHIND_PROXY=1` | ใช้เมื่ออยู่หลัง reverse proxy เพื่อให้เชื่อ header `X-Forwarded-*` |
| `DJANGO_SECRET_KEY` | ถ้าไม่ตั้ง ระบบจะสร้างให้อัตโนมัติและเก็บไว้ที่ `web/.secret_key` |

ถ้าจะเปิดให้เครื่องอื่นในเครือข่ายเข้าใช้ ควรวางไว้หลัง reverse proxy ที่มี HTTPS (เช่น Caddy หรือ nginx) แล้วตั้ง `DJANGO_HTTPS=1`
